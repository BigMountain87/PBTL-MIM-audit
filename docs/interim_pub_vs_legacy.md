# 중간 결과 — pub arm이 legacy arm보다 pretender가 훨씬 적다 (2026-09-07)

**상태: 중간 확인.** 아래 표는 B·C(40 설계) 시점의 첫 기록이고, §'3구조 seed 42 완료'가 최신이다. A와 seed 123/777,
그리고 T55 통제 실험은 아직 계산 중이므로 **본문에 쓰기 전 전체 179(또는 pub arm의 최종 n)로
다시 계산해야 한다.** 여기 숫자는 `results_pub/rcwa_{B,C}_v8.npz`와 `results_v8/`의 같은
파일에서 직접 읽은 것이고, 어떤 원고 텍스트도 아직 이 값으로 바꾸지 않았다.

## 무엇이 달라졌나

| | legacy arm (as-submitted 2026-03 릴리스) | pub arm (인쇄본 파이프라인) |
|---|---|---|
| forward test MAE (seed 42) | B 3.19 % · C 3.86 % | **B 1.72 % · C 2.11 %** |
| surrogate-claimed (τ = 5 %) | 20/20 · 20/20 | 20/20 · 20/20 |
| oracle-confirmed | 11/20 · 7/20 | **17/20 · 18/20** |
| **pretenders** | 9/20 [25.8, 65.8] · 13/20 [43.3, 81.9] | **3/20 [5.2, 36.0] · 2/20 [2.8, 30.1]** |
| B+C 합산 pretender | **22/40 = 55.0 %** [39.8, 69.3] | **5/40 = 12.5 %** [5.5, 26.1] |
| median Δ (RCWA − Surr) | B 3.19 pp · C 4.02 pp | B 2.34 pp · C 0.21 pp |
| max Δ | B 31.03 pp · C 13.67 pp | B 12.11 pp · C 4.66 pp |

두 비율의 차이는 우연이 아니다: Fisher exact **p = 1.1 × 10⁻⁴**, odds ratio 0.117.

## 읽는 법

- 서로게이트 자체가 훨씬 정확해졌다(전방 MAE가 대략 절반). pretender는 서로게이트 오차의
  꼬리에서 나오므로, 전방 정확도가 좋아지면 pretender가 줄어드는 것은 방향상 예상되는 일이다.
- 두 arm은 체크포인트·데이터 풀·솔버 설정(고정 order 5·complex128 ↔ 파장별 adaptive
  order 9/13/17·complex64·Johnson–Christy)이 **모두** 다르다. 따라서 이 표는 "오라클을
  바꿨더니 달라졌다"가 아니라 **"as-submitted 릴리스에서 인쇄본 파이프라인으로 갈 때
  reliability가 얼마나 좋아졌나"** 로 읽어야 한다. 어느 요인이 얼마나 기여했는지는 이 실행만으로
  분해되지 않는다.
- 질적 주장은 살아 있다: pub arm에서도 **40 설계 전부가 서로게이트의 5 % 자기검증을 통과했고
  그중 5개를 레퍼런스 솔버가 기각**했다. 자기검증은 여전히 정보가 없다. 다만 **크기가 다르다.**

## 원고에 미치는 영향 (저자 결정 필요)

1. 초록·§5·기여 목록의 헤드라인 "**95 / 179 (53 %) pretenders**"는 pub arm에서 성립하지 않을
   가능성이 높다. 현재 추세대로면 pub arm 헤드라인은 한 자리 %~10 %대가 된다.
2. 제목 "Transferability Is Not Invertibility"와 §4.1의 논지는 유지 가능하지만, **강도를
   낮춰야 한다**(“절반이 가짜”가 아니라 “정확한 서로게이트에서도 10 % 안팎이 가짜”).
3. legacy arm이 SI로 가면, 두 arm의 대비 자체가 새로운 결과가 된다 — 파이프라인 교정이
   inverse reliability를 얼마나 끌어올렸는지에 대한 정량적 진술.
4. τ 스윕·심각도 밴드·detector AUROC·H1 순서 검정은 전부 pub 수치로 재계산해야 한다
   (pretender가 적어지면 검정력이 더 떨어진다 — 5/40에서 구조 간 순서를 검정하는 것은
   사실상 불가능하다).

## 3구조 seed 42 완료 (2026-09-07 12:30)

A seed 42까지 끝나 `rcwa_A_v8.npz`가 나왔다. 세 구조 60 설계의 pub arm 수치:

| 구조 (인쇄 *r*) | n | surrogate-claimed | oracle-confirmed | pretender | median Δ | max Δ | mean Surr / RCWA MAE |
|---|---|---|---|---|---|---|---|
| B (+0.96) | 20 | 20 | 17 | **3** [5.2, 36.0] | +2.34 | +12.11 | 0.50 % / 3.74 % |
| A (+0.83) | 20 | 20 | 19 | **1** [0.9, 23.6] | +1.45 | +9.90 | 0.46 % / 2.57 % |
| C (+0.65) | 20 | 20 | 18 | **2** [2.8, 30.1] | +0.21 | +4.66 | 1.31 % / 1.85 % |
| **합산** | 60 | **60/60** | 54 | **6/60 = 10.0 %** [4.7, 20.1] | | | |

legacy arm의 같은 seed는 31/60 = 51.7 % [39.3, 63.8]이었다. Fisher exact **p = 1.0 × 10⁻⁶**,
odds ratio 0.104.

읽는 법 세 가지:

1. **자기검증은 여전히 무정보**다. 60개 전부가 서로게이트의 5 % 자기검증을 통과했고 그중 6개를
   레퍼런스 솔버가 기각했다. "서로게이트가 성공이라고 말한 것"과 "실제 성공"은 여전히 다른 집합이고,
   그 차이는 솔버를 부르지 않고는 알 수 없다.
2. **크기는 10 %대**다. 53 %가 아니다. 초록·§5·기여 목록의 헤드라인 수치는 못 쓴다.
3. **순서 가설의 검정력은 사실상 사라졌다.** pretender가 B 3 / A 1 / C 2이면 인쇄 *r* 순서(B > A > C)
   에서도 단조가 아니고, B-vs-C Fisher p = 1.000이다. H1a–c는 pub arm에서 "지지되지 않음"이 아니라
   **"이 표본 크기로는 검정 불가"** 에 가깝다. 3 seed(180 설계)를 다 모아도 pretender 총수가
   20 안팎일 것으로 보이므로 상황은 크게 달라지지 않는다.

### 순서 가설이 뒤집혔다 (예비 계산, 정식 수치는 stage 5의 reliability JSON에서)

pub arm의 구조별 pretender 비율은 B 15.0 % [8.1, 26.1] · A 3.4 % [0.9, 11.5] · C 8.3 % [3.6, 18.1]다.

| 순서 규약 | 비율(순서대로) | 단조? | Cochran–Armitage | 양극단 Fisher |
|---|---|---|---|---|
| 인쇄 *r* (B > A > C) | 15.0 / 3.4 / 8.3 | 아니오 | z = −1.28, p = 0.201 | 0.394 |
| **예비 *r* (A > C > B) — 사전 명세한 규약** | **3.4 / 8.3 / 15.0** | **예** | **z = +2.22, p = 0.026** | 0.053 |
| 작동대역 TMM MAE (A < B < C) | 3.4 / 15.0 / 8.3 | 아니오 | z = +0.94, p = 0.350 | 0.439 |

legacy arm에서는 어떤 규약으로도 지지되지 않았는데, **pub arm에서는 사전 명세한 예비 *r*
규약에서 예측 방향으로 단조이고 추세 검정이 명목상 유의하다.** 다만

- ~~보정 후 0.06–0.10이 될 것~~ — **틀렸다 (2026-09-09 정정)**. legacy arm의 보정 폭을 계산 없이
  유추한 결과였다. 실제로 계산하면 pub arm의 pretender 지시자 ICC(1)는 A −0.019 · B +0.103 ·
  C +0.791이고, 추세 통계량의 분산은 각 군을 n_i(x_i − x̄)²로 가중한다. **C는 점수 범위의
  한가운데(x = 1)라 가중치가 0.002로 사실상 0**이므로, C의 큰 ICC가 분산에 거의 들어오지 않는다.
  분산 팽창은 1.103배에 그치고 **z = 2.114, p = 0.0345** — 유의성이 사라지지 않는다.
  (`n_i(x_i − x̄)²` = A 59.66 · C 0.002 · B 59.33.)
- Holm 보정 대상 검정군에 들어가면 올라간다. 다만 검정군을 이 결과에만 선택적으로 적용하면 안 된다.
- 정식 수치는 stage 5가 `reliability_*.json`을 쓴 뒤 `synthesize.py`/`gate_summary_v10.py`(T16)로
  내야 한다. **이 표는 그 전의 예비 확인이고, 원고에는 아직 쓰지 않는다.**

이 결과가 사실로 굳으면 초록·§3.3·§4.2의 "어떤 사전 명세 순서도 유의에 이르지 못한다"는
문장이 바뀌어야 한다 — 방향이 반대다.


## 두 번째 역전 — C의 자기보고는 정보를 담고 있다 (2026-09-09, codex 리뷰가 지적)

pub arm에서 구조 C의 ρ(RCWA, Surr)는 seed 42/123/777에서 **+0.750 (p = 1.4 × 10⁻⁴) ·
+0.829 (6.4 × 10⁻⁶) · +0.719 (3.6 × 10⁻⁴)** 로, 9개 검정 Holm 보정 후에도 전부 유의하다.
C의 pretender를 서로게이트 자신의 MAE만으로 가려내는 pooled AUROC는 **0.9855**다(원고 표 10은
0.68). 따라서 원고 569행의 "자기보고는 쓸 만한 순위 정보를 담지 않는다 … 어느 것도 9-검정
보정을 통과하지 못한다"는 **pub arm에서 거짓**이다. 검정력 부족이 아니라 방향이 반대다.

정확한 구분은 이렇다: **고정된 5 % 합격/불합격 지시자는 모두가 통과하므로 아무것도 구분하지
못하지만, 연속 점수로서의 서로게이트 MAE는 여전히 판별력을 가진다.** 단 C의 AUROC는 서로 다른
타깃 2개에서 나온 5건의 사건에 기대고 있어 배포 가능한 인증 임계값을 세우지는 못한다.
